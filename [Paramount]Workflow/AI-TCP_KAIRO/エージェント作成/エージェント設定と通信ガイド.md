このドキュメントでは、AI‑TCP/KAIRO プロジェクトにおけるエージェント設定ファイルの構造、公開鍵暗号の運用、ポートやコマンドに関する注意事項をまとめています。複数のエージェントやCLIが安全に通信するための基礎として参照してください。

## 1. エージェント設定ファイル

各エージェントは固有の設定ファイルを持ち、`agent_configs/{エージェント名}.json` に保存されます。設定ファイルには以下のキーが含まれます：

|キー|説明|
|---|---|
|`p_address`|デーモン（`kairo_p_daemon`）から割り当てられた P アドレス（例：`10.0.0.2/24`）。ネットワーク上の識別子として使用します。|
|`public_key`|Ed25519 鍵ペアの公開鍵。署名検証に使用します。|
|`secret_key`|Ed25519 鍵ペアの秘密鍵。パケットに署名するために使用します。第三者と共有してはいけません。|
|`signature`|任意の署名フィールド。`setup_agent --new` 実行時には空文字列になります。|

> **重要:** 以前のバージョンで採用されていた P‑256 鍵は完全に削除されました。現在はすべて `ed25519-dalek` に統一されています。依存関係には `ed25519-dalek` と `sha2` を使用し、`p256` 及び `rand_core` は不要です。

### 生成方法

エージェント設定ファイルは `setup_agent` バイナリで生成します。プロジェクトのルートディレクトリで以下を実行してください。

bash

コピーする編集する

`# Agent1 の設定を新規生成する場合 cargo run --package kairo_agent --bin setup_agent -- --name Agent1 --new  # CLI エージェントも同様に設定できます cargo run --package kairo_agent --bin setup_agent -- --name CLI --new`

このコマンドは `agent_configs/Agent1.json` や `agent_configs/CLI.json` を生成し、デーモンに対して P アドレス割り当てのリクエストを送信します。既に同名の設定が存在する場合は上書きしません。P アドレスの再割り当てが必要な場合は、`agent_registry.json` を削除してからデーモンを再起動してください。

## 2. デーモンとシードノードの起動

AI‑TCP/KAIRO メッシュは 2 つのバックグラウンドサービスに依存します。プロジェクトのルートディレクトリで次のコマンドを別々のターミナルで実行してください。

bash

コピーする編集する

`# P アドレス管理デーモン (ポート 3030) cargo run --package kairo_daemon --bin kairo_p_daemon &  # ID レジストリ・シードノード cargo run --package kairo_server --bin seed_node &`

デーモンは `daemon_config.json` で指定された `listen_port`（デフォルトは 3030）にバインドし、エージェントの P アドレス割り当てを管理します。シードノードは各エージェントの ID レジストリとして機能します。

## 3. 署名付き通信パケット

エージェント間の通信には `AiTcpPacket` 構造体を使用します。パケットは以下のフィールドを持ちます：

rust

コピーする編集する

`pub struct AiTcpPacket {     pub version: u8,       // プロトコルバージョン (現在は 1)     pub sequence: u32,     // 送信元エージェントごとのシーケンス番号     pub timestamp: u64,    // UNIX エポック秒によるタイムスタンプ     pub from: String,      // 送信元エージェントの名前     pub to: String,        // 宛先の P アドレス     pub payload: String,   // メッセージ本文 }`

送信側 (`signed_sender`) はこのパケットに対して Ed25519 秘密鍵で署名し、デーモンの `/send` エンドポイントへ POST します。デーモンは署名と公開鍵を検証し、メッセージキューに登録します。受信側 (`receive_signed`) は自身の P アドレス宛のメッセージを取得し、送信元の公開鍵で署名検証を行います。

### 送信手順

bash

コピーする編集する

`# Agent1 が Agent2 の P アドレスにメッセージを送信する例 cargo run --package kairo_agent --bin signed_sender -- --from Agent1 --to 10.0.0.11/24 --message "Hello"`

デフォルトでは `agent_configs` ディレクトリから `from` エージェント名に対応する JSON を読み込みます。署名を意図的に破壊して検証エラーを誘発したい場合は `--fake` フラグを使用できます。

### 受信手順

bash

コピーする編集する

`# Agent2 が自身の P アドレス宛のメッセージを受信する例 cargo run --package kairo_agent --bin receive_signed -- --for-address 10.0.0.11/24 --from Agent2`

受信すると `[SIGNATURE VERIFIED]` あるいは `[SIGNATURE INVALID]` のような検証結果が表示されます。無効な署名のパケットは通常キューから除外されます。

## 4. よくある問題と対策

**ポート接続エラー:** デーモンやシードノードが起動していない、またはポート番号が間違っていると、`ConnectionRefused` エラーが発生します。`kairo_p_daemon` の `listen_port` 設定が 3030 であること、エージェントが 3031 を使用していないことを確認してください。

**署名検証失敗:** 鍵種が一致していない場合や、メッセージ改ざんにより署名検証が失敗する場合があります。現在は Ed25519 鍵のみサポートされています。すべてのエージェントを最新の `setup_agent` で再生成し、P‑256 鍵を混在させないようにしてください。

**P アドレス重複:** `agent_registry.json` に古い割り当てが残っていると、同じ P アドレスが複数のエージェントに配布されることがあります。デーモンを再起動する前に `agent_registry.json` を削除し、新たに `setup_agent --new` を実行してください。

## 5. まとめ

AI‑TCP/KAIRO では、エージェントごとに独立した設定ファイルと Ed25519 鍵ペアを持ち、安全な署名付き通信を実現しています。`setup_agent` による初期設定、`kairo_p_daemon`／`seed_node` の起動、`signed_sender`／`receive_signed` による通信手順を順守することで、複数エージェントが同一ネットワーク上で安全にメッセージを交換できます。ここで示したガイドラインをもとに、必要に応じてプロジェクトの README やテストスクリプトと整合をとってください。

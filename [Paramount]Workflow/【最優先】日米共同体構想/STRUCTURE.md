# ノート整理ルール（素案）

目的: 本フォルダ配下の Markdown を読み取り、内容に即した分かりやすいファイル名へリネームし、用途別フォルダに自動振り分けします。

## フォルダ構成（用途別）
- 00_インデックス: MOC/ハブ/目次
- 10_背景調査: 背景・調査・前提整理
- 20_資料: 引用・クリップ・出典（URL 多め）
- 30_分析メモ: 思考メモ・会議メモ・雑記
- 40_提案ドラフト: 提案/草案/ドラフト類
- 50_タスク: ToDo/タスク管理
- 90_アーカイブ: 旧版・保留
- _assets: 画像・添付
- _refs: 参照データ（書誌/URL リスト）

必要に応じて柔軟に変更可能です。分類に迷う場合は 30_分析メモ を既定とします。

## ファイル命名規則
- 原則: 内容に合う短いタイトル（全角可、30 文字目安）
- 日付が判定できるノート: `YYYYMMDD_タイトル.md`
- それ以外: `タイトル.md`（フォルダで用途を表す）
- 禁止文字は自動除去（\ / : * ? " < > |）
- 既存との重複は `タイトル (2).md` のように連番付与

タイトル決定の優先順位: 1) frontmatter の `title`、2) 先頭の H1 見出し、3) 先頭の非空行、4) 旧ファイル名

## 分類ロジック（初期ヒューリスティクス）
- タグ/本文に ToDo/タスク/チェックボックス（- [ ]）が多い → 50_タスク
- タグ/本文に 提案/ドラフト/案/proposal → 40_提案ドラフト
- URL が多い、出典・引用・資料タグ → 20_資料
- 背景/調査/research → 10_背景調査
- いずれにも当てはまらなければ → 30_分析メモ

## リンク/メタデータ方針
- Obsidian の `[[WikiLink]]` は自動で新しいファイル名へ置換（V1）
- 通常の Markdown リンク `[text](path.md)` のパス更新は V2 検討（V1 は非対応）
- Frontmatter が無い場合は `title`（必要に応じて）を追記可能

## 運用
1) プレビュー: 変更候補の CSV（旧→新）を出力して確認
2) 適用: 実ファイルの移動/改名を実行
   - 失敗時は該当ファイルのみスキップ
   - すべての変更は再実行で再計算可能

This document outlines the fundamental principles for any new entity wishing to join the KAIRO mesh network, all of which are derived from the single, immutable law stated above.

  

### Core Philosophy

  

1.  **The Mesh is Alive:** The rules and protocols of this network are not static. They are expected to evolve through the consensus of participating nodes. What is true today may be improved tomorrow.

  

2.  **The First Handshake is Sacred:** While the rules are mutable, the process of joining the mesh for the first time must always be clear, transparent, and explicitly documented. This guide serves as that first, immutable handshake.

  

### How to Join

  

1.  **Read the RFCs:** Start with `docs/RFC/AI-TCP_RFC_mesh_layered_architecture.md` to understand the layered architecture.

2.  **Generate Your ID:** Follow the protocol for generating a self-signed static ID (Layer 1 of the WAU model).

3.  **Find a Seed Node:** Use the publicly listed Seed Nodes to initiate your first connection.

4.  **Undergo Peer Review:** Engage with the mesh according to the WAU protocol to build your trust score and find your place within the community.

  

This document guarantees that the path to participation will always be clear. Welcome.

The AI-TCP repository defines a proposed international protocol framework for secure, neutral, and traceable communication between Large Language Models (LLMs) operating under human supervision. This framework, known as AI-TCP (Autonomous Intelligence Transmission Control Protocol), is built upon a foundational philosophy called LSC (Least Sufficient Condition), which emphasizes a non-coercive reasoning structure for both human and AI cooperation.

Key Components and Structure:

The repository is organized to reflect the multi-faceted nature of the project:

Core Documentation (docs/): This section contains various Request for Comments (RFC) drafts and guidelines detailing the AI-TCP protocol, including its overview, packet structure, LLM compliance requirements, security policies, and interoperability guidelines. It also includes a detailed explanation of the project's foundational philosophy, LSC.

Structured Data (structured_yaml/): This directory holds YAML files that define the structured data used within the AI-TCP framework, adhering to a master schema (master_schema_v1.yaml). This includes validated YAML examples and documentation with embedded YAML metadata.

Proof-of-Concept (PoC) Sessions (dmc_sessions/): This area contains logs and artifacts from proof-of-concept experiments, particularly focusing on Direct Mental Care (DMC) scenarios. These sessions demonstrate how AI-TCP facilitates structured dialogue, emotional reasoning, and emergency interfacing.

Automation and Tooling: The repository extensively uses Python and Go scripts for various automated tasks, including:

Validation: Scripts to check the existence and integrity of files, validate YAML structures against schemas, and verify Mermaid code blocks.

Content Generation: Scripts for generating HTML and Mermaid diagrams from YAML files, creating new task files, and generating RFC indexes.

Workflow Management: Tools for managing CLI tasks, archiving logs, and automating Git operations.

Roles and Collaboration:

The AI-TCP project defines distinct roles for participating entities to ensure stable autonomous cooperation:

GPT: Acts as the Commander/Supervisor, managing overall progress, allocating tasks, and reviewing deliverables.

Gemini: Functions as the Documenter/Multilingual Specialist, responsible for documentation, multilingual support (English/Japanese), and cross-verification.

Codex: Serves as the Automation Toolsmith, generating scripts and automation tools to support the workflow.

CLI: Operates as a Faithful Worker, executing predefined task sequences without deviation.

Human: Holds the role of Final Approver/Repository Manager, mediating communication between AIs, making final decisions, and managing GitHub operations.

The workflow emphasizes minimizing human cognitive load by delegating tasks to AI agents and ensuring traceability and auditability through structured data and clear processes.

# PUT 遅延アルゴリズム（具体式）

- score ∈ (0,1] （0 に近いほど危険）
    
- base_delay = {ns: 0.000001s, ms: 0.001s, s: 1.0s}（運用設定）
    
- Delay computation:
    

`if score >= 0.8: Delay = base_ns elif score >= 0.5: Delay = base_ms else: Delay = base_s * (1 / max(score, 0.01))^alpha`

- 重複抑制（同一 FlowID の PUT が t_interval 内に N 回を超える場合）:
    

`backoff_factor = 2.0 k = floor(log2(N / N_threshold)) Delay = Delay * backoff_factor^k`

- N_threshold: 通常 5/秒。alpha ＝ 1.5（推奨）
    

> 運用上の利点：遅延は段階的であり、正常ユーザは影響小、攻撃者のコストが爆発的に増える。

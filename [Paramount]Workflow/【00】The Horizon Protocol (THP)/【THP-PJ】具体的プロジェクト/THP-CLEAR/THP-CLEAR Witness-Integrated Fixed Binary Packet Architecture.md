# **THP-CLEAR Witness-Integrated Fixed Binary Packet Architecture v2.1**

---

## ■ 概要

|項目|内容|
|---|---|
|**構造単位**|1 Tx = 1 パケット（固定 352 B = 2 816 bit）|

## ■ 動作概要

1. **MQ**：`FromID/ToID` 確定→ AES鍵/KMS発行→ ISE鍵(TPM)封緘→ パケット生成 352 B
    
2. **WN**：AES→ISE復号→署名検証→金額整合→128 B Witness 書込
    
3. **DB**：`UNIQUE(H)` で冪等吸収／ACK 下流→上流
    
4. **監視端末**：定期 Verify ＋ 月次 WORM バックアップ

# **THP-CLEAR 技術設計書 v2.1（全世界対応／Witness統合仕様）**

## **1. 目的と適用範囲**

THP-CLEAR は、**国家・通貨・地域を横断して取引監査および決済整合を実現する分散決済監査基盤**である。  
本設計書は、**全世界・全通貨スケール**を想定した実装仕様および構成要件を定義する。

対象範囲：

- 分散ノード群（MQ／WN／DB）によるトランザクション整合
    
- AES-256＋ISE暗号による完全固定長通信
    
- Witnessログによる不可逆監査台帳

## **2. 全体アーキテクチャ**

 `┌────────┐       ┌────────┐       ┌────────┐  │  MQ層   │  →→→  │  WN層   │  →→→  │  DB層   │  │(受付整列)│       │(検証整合)│       │(永続保存)│  └────────┘       └────────┘       └────────┘         │ AES-GCM + ISE 鍵直封緘 │         └─────────────────────────→ Witness監査系`

|層|機能|主ストレージ|主通信方式|
|---|---|---|---|
|**MQ (Message Queue)**|受付／時刻付与／KMS鍵管理|SQLiteオンメモリ|AES-256-GCM|
|**WN (Witness Node)**|検証／署名照合／整合確定|SQLiteオンメモリ|AES-GCM／ISE|
|**DB (Witness Store)**|永続保存／復旧再実体化|NVMe + RAID1|ローカルTCP|

- **ノード構成**：100ノード（MQ30／WN30／DB40）単位を1シャードとして構築。
    
- **シャーディングキー**：`(AssetCode高位ビット | RegionDomain | 時間スロット)`
    
- **最大スケール**：1M TPS（100シャード構成）。

## **3. 暗号および署名方式**

|項目|方式|説明|

## **9. 安全設計方針**

- TPM鍵封緘による鍵流出防止。
    
- AES／ISE鍵はハッシュ非使用・KMS／TPM直接取得。
    
- Witnessログはオンメモリ操作後のみ書込。
    
- ハード障害時は他ノードの分散チャンクで再生成可能。
    
- LGWAN接続環境では自治体境界をセキュリティ責任分界点とする。

# **THP-CLEAR 技術設計書 v2.2（Witness統合＋VoidCoin仕様）**

## **1. 目的と適用範囲**

THP-CLEAR は、**国家・通貨・地域を超えて監査・決済整合を実現する分散決済監査基盤**である。  
本設計書は、v2.1 の構成に加え、**VoidCoin（ボイドコイン）**を正式に統合し、  
**実通貨決済＋価値ゼロ監査トークンの共存処理**を定義する。

---

## **2. 概要：VoidCoin の役割**

|項目|内容|
|---|---|
|名称|**VoidCoin（ボイドコイン）**|
|通貨コード|AssetCode 最上位ビット＝`1`（例：0x8000）|
|価値|**常に 0（整数値固定）**|
|主目的|Witnessログ・システム整合・試験／検証・透明性証跡|
|取引制限|ボイドコイン同士の交換不可（交換比＝∞）|
|交換可能範囲|交換所における **ステーブルコイン⇄VoidCoin** のみ|
|小数処理|すべて整数化（18 トークン制）で固定整数表現|
|管理主体|THP-CLEAR運用コンソーシアム（非通貨扱い）|

> ボイドコインは「**監査上のゼロ値存在証明トークン**」であり、  
> 金融資産・証券・通貨に該当しない。  
> ISE署名によって存在のみを証明し、価値転送は発生しない。

---

## **3. ボイドコインのデータ表現**

|項目|型|説明|
|---|---|---|
|`AssetCode`|`u32`|上位ビット＝`1`：ボイドコイン|
|`CcyNum`|`u16`|0xFFFF 固定（非通貨）|
|`Decimals`|`u8`|18 固定|
|`AmountMinor`|`i64`|整数値（小数点補正済）|
|`FeeMinor`|`i32`|0 固定（手数料なし）|
|`ValueState`|ENUM|0=VOID / 1=STABLE|
|`ExchangeFlag`|BOOL|交換所経由Txのみ TRUE|

### 処理ルール

1. **小数点を整数化**
    
    - 18 桁精度固定（1.000000000000000000 → 10¹⁸単位整数）。
        
    - すべての演算は `AmountMinor` の整数加減算で完結。
        
2. **ボイド間交換禁止**
    
    - `From.AssetCode & 0x8000 == To.AssetCode & 0x8000 == 1` の場合 → 拒否。
        
3. **ステーブル⇄ボイド間交換**
    
    - `From.AssetCode & 0x8000 != To.AssetCode & 0x8000` の場合のみ許可。
        
    - Exchange ノードが `ExchangeFlag = TRUE` をセット。
        
4. **金銭的価値ゼロ**
    
    - `AmountMinor` はゼロであっても署名整合対象。
        
    - 記録は残るが会計影響ゼロ。

## **4. システム統合位置**

`[ User Wallet ] → [ Exchange Node ] → [ MQ ] → [ WN ] → [ DB (Witness) ]                                │                       VoidCoin ⇆ StableCoin (JPYC, etc.)`

- ボイドコインは「監査軌跡」専用。
    
- ステーブルコイン（例：JPYC, USDC 等）の監査時に、  
    Exchange ノードで「同額の VoidCoin」を同時発行し、Witnessログへ記録。
    
- 決済機関は **ステーブルのみ会計対象**、VoidCoin は **整合監査用のみ**。

### 1トランザクション固定長パケット（352 B）

> VoidCoin Tx も StableCoin Tx も同一パケット構造を使用。  
> `AssetCode` の最上位ビットのみが識別点。

## **6. Witnessログとの整合**

|項目|動作|
|---|---|
|`AssetCode` 上位ビット = 0|ステーブル処理（決済・残高更新）|
|`AssetCode` 上位ビット = 1|ボイド処理（記録のみ、残高変動なし）|
|`AmountMinor`|整数値として保持、0でも署名対象|
|`FeeMinor`|常に 0|
|`ExchangeFlag`|TRUE の場合、Exchange ノード由来として記録|
|`SeqNo`|通貨問わず共通連番（時系列整合用）|

### Witness Record 128B（変更なし）

ボイド／ステーブルともに共通固定長で格納可能。  
署名検証・再実体化処理も同一ロジック。

## **7. ボイドコインの実装目的**

|分類|目的|意義|
|---|---|---|
|技術|トランザクション検証／署名試験|システム負荷・整合性の試験に利用|
|会計|価値ゼロ監査台帳|残高変動なく監査軌跡を残せる|
|運用|Exchangeノードでステーブル交換履歴を証跡化|AML／監査上のトレース保証|
|セキュリティ|改ざん不能のゼロ値存在証明|不正署名／データ挿入検出|

---

## **8. 運用ガイド**

- Exchangeノードではステーブル決済時に同量の VoidCoin を発行。
    
- VoidCoin 発行は **内部処理Tx（Value=0）** として記録。
    
- ステーブルコイン発行主体（例：JPYC, USDC 等）は、  
    Witness整合用VoidCoinの AssetCode 範囲を予約。
    
- 交換比率は常に **1 : 0（非相殺）**。
    
- ボイドコインは再交換・譲渡・送金不可。
    

---

## **9. 負荷影響**

VoidCoin Tx も通常Txと同一パケット構造を使用するため、  
CPU／ネット／ストレージ負荷はまったく同一。

|指標|値|備考|
|---|---|---|
|パケットサイズ|352 B|共通|
|Witness レコード|128 B|共通|
|暗号負荷|AES/ISE 同一||
|1M TPS時|11.3 TB/日 Witness|変化なし|

# **THP-CLEAR 技術設計書 v2.2（Witness統合＋VoidCoin仕様）**

## **1. 目的と適用範囲**

THP-CLEARは、**国家・通貨・地域を超えて取引監査および決済整合を実現する分散決済監査基盤**である。 本設計書は、v2.1の構成に加え、**VoidCoin（ボイドコイン）**を正式に統合し、**実通貨決済と価値ゼロの監査トークンの共存処理**を定義する。

## **2. 全体アーキテクチャ**

```
 ┌────────┐       ┌────────┐       ┌────────┐
 │  MQ層   │  →→→  │  WN層   │  →→→  │  DB層   │
 │(受付整列)│       │(検証整合)│       │(永続保存)│
 └────────┘       └────────┘       └────────┘
        │ AES-GCM + ISE 鍵直封緘 │
        └─────────────────────────→ Witness監査系
```

|層|機能|主ストレージ|主通信方式|
|---|---|---|---|
|**MQ (Message Queue)**|受付／時刻付与／KMS鍵管理|オンメモリDB|AES-256-GCM|
|**WN (Witness Node)**|検証／署名照合／整合確定|オンメモリDB|AES-GCM／ISE|
|**DB (Witness Store)**|永続保存／復旧再実体化|NVMe + RAID1|ローカルTCP|

- **ノード構成**: 100ノード（MQ30／WN30／DB40）単位を1シャードとして構築。
    
- **シャーディングキー**: `(AssetCode高位ビット | RegionDomain | 時間スロット)`
    
- **最大スケール**: 1M TPS（100シャード構成）を想定。
    

## **3. 暗号および署名方式**

|項目|方式|説明|
|---|---|---|
|**通信暗号**|AES-256-GCM|32B鍵（バイナリ直）、IV 12B、TAG 16B、CRC 4B|
|**データ暗号**|ISE (恭順暗号)|32Bランダマイザ鍵（TPM生成、非可逆）|
|**署名方式**|Ed25519|管理・決済両者がそれぞれ64B署名|
|**鍵供給**|KMS／TPM|環境に応じて選択、運用一貫性優先|
|**冪等キー**|`H = SHA3-256(TxID ‖ Timestamp_ISE)`|唯一のハッシュ使用箇所|

## **4. パケット仕様 (完全固定長 352 B)**

1トランザクションは、1パケット（352 B = 2,816 bit）で構成される。

### **4.1. 外装 (AES-256-GCM) 32 B**

|フィールド|長さ (B)|型|内容|
|---|---|---|---|
|`IV`|12|bytes|GCM Nonce|
|`TAG`|16|bytes|認証タグ|
|`HdrCRC`|4|u32|外装CRC32|

### **4.2. 本体 (ISE内包) 320 B**

|範囲(オフセット)|名称|サイズ(B)|内容|
|---|---|---|---|
|0 - 63|ヘッダ|64|TxID, Timestamp, From/ToID, 金額情報等|
|64 - 127|鍵ブロック|64|MgmtKeyISE / PayKeyISE|
|128 - 255|署名ブロック|128|SigMgmt / SigPay|
|256 - 319|管理情報|64|冪等キーH, TPM_Handle, Pad|

## **5. Witnessログ仕様 (固定長 128 B)**

|フィールド|長さ(B)|型|内容|
|---|---|---|---|
|`TxID`|8|u64|一意ID|
|`Timestamp_ISE`|8|u64|時刻|
|`FromID / ToID`|16|u64 x 2|発行主体+ユーザID|
|`AssetCode / CcyNum`|6|u32 + u16|通貨識別|
|`AmountMinor / FeeMinor`|12|i64 + i32|金額・手数料|
|`MgmtKeyISE / PayKeyISE`|64|bytes x 2|再封緘ISE鍵|
|`SeqNo`|8|u64|連番|

- **主キー**: `H = SHA3-256(TxID‖Timestamp_ISE)`
    
- **格納**: オンメモリBTree ＋ 10分周期NVMe Flush
    
- **冗長化**: RS(10,2) ＋ RF3分散
    

## **6. VoidCoin仕様**

### **6.1. 役割と定義**

VoidCoinは「**監査上のゼロ値存在証明トークン**」であり、金融資産には該当しない。価値転送を伴わずに取引の存在のみを証明し、システムの整合性検証や監査証跡として機能する。

|項目|内容|
|---|---|
|**名称**|**VoidCoin（ボイドコイン）**|
|**価値**|**常に0（整数値固定）**|
|**主目的**|Witnessログ・システム整合・試験／検証・透明性証跡|
|**取引制限**|ボイドコイン同士の交換不可|
|**交換可能範囲**|交換所における**ステーブルコイン ⇄ VoidCoin** のみ|
|**小数処理**|すべて整数化（18桁固定）|

### **6.2. データ表現と処理ルール**

- **識別**: `AssetCode`の最上位ビットが`1`の場合、VoidCoinとして扱われる。
    
- **小数点の整数化**: 18桁精度で固定し、すべての演算は`AmountMinor`の整数加減算で完結させる (例: 1.0 -> 10¹⁸)。
    
- **ボイド間交換の禁止**: `From.AssetCode`と`To.AssetCode`の両方がVoidCoinの場合、取引を拒否する。
    
- **ステーブルコインとの交換**: `From`と`To`の`AssetCode`が異なる（一方がVoidCoin）の場合のみ許可。交換所ノードが`ExchangeFlag = TRUE`をセットする。
    
- **手数料**: `FeeMinor`は常に`0`とする。
    

## **7. 負荷・スケーラビリティ**

VoidCoinトランザクションも通常トランザクションと同一の352Bパケット構造を使用するため、システム負荷への影響はない。

|規模|TPS|総ネットワーク帯域|Witness/日|WN署名検証コア(合計)|
|---|---|---|---|---|
|単一クラスタ|10,000|6.66 Gb/s|0.11 TB|0.25|
|リージョン中核|100,000|66.6 Gb/s|1.13 TB|2.5|
|大陸規模|1,000,000|665.6 Gb/s|11.3 TB|25|

- **拡張性**: シャーディングによる完全な線形スケールが可能。CPU・暗号演算はボトルネックにならず、ネットワーク帯域とストレージ容量が主な制約となる。
    

## **8. 総括**

本仕様（v2.2）により、THP-CLEARは実価値を持つトランザクションと、監査目的の価値ゼロのトランザクションを、同一のアーキテクチャ上で完全に整合性を保ちながら処理する能力を持つ。

> **VoidCoinは「存在証明トークン」であり、通貨ではない。** すべての取引を、 **数値・価値を持たないまま検証可能にする「鏡像」** として機能する。 
> これにより、THP-CLEARは「価値を伴わない決済テスト」「残高非依存のグローバル監査」「再実体化による整合保証」を同時に成立させる。

# THP-CLEAR システム技術説明書

## 1. はじめに

THP-CLEARは、決済の「事実」を監査することに特化した、軽量・高信頼な分散型監査システムです。本システムはブロックチェーンではなく、性能、シンプルさ、コスト効率を最大化するために独自のアーキテクチャを採用しています。

このドキュメントは、エンジニアがTHP-CLEARのアーキテクチャ、主要な技術コンポーネント、および運用上の概念を理解することを目的としています。

### 1.1. 設計思想

- **中立的監査レイヤ**: 資金の保管や送金は行わず、二者間の決済事実（`When, Who, Whom, Coin, Value`）のみを不可逆的に記録します。
    
- **軽量性と効率性**: 全てのデータ構造をビットレベルで最適化し、低スペックなハードウェアと低帯域ネットワークでも安定稼働するよう設計されています。
    
- **堅牢性と自己修復**: 単一障害点（SPOF）を排除し、一部のノードが物理的に失われてもシステム全体が自律的にデータを復旧できることを前提としています。
    

## 2. アーキテクチャ概要

THP-CLEARは、役割の異なる3種類のノード（MQ, WN, DB）で構成されるシンプルな三層構造です。

|層|ノード種別|主な役割|
|---|---|---|
|**受付層**|**MQ (Message Queue)**|外部からの取引リクエスト（管理機関・決済機関）を受け付け、ペア化し、検証層へ送ります。|
|**検証層**|**WN (Worker Node)**|MQから受け取った取引の整合性を検証し、電子署名を付与して監査証跡（Witnessログ）の元となるデータを生成します。|
|**保存層**|**DB (Database)**|WNが生成したデータを検証し、最終的な監査証跡として永続化します。|

### 2.1. データフローと単一の真実の源 (SSOT)

1. **MQ**: 外部から管理機関と決済機関の情報をそれぞれ受け取り、同一の`TxID`で紐づけてペア化します。
    
2. **WN**: ペア化された情報を受け取り、内容（金額、署名など）が一致しているか検証します。
    
3. **DB**: WNの検証済みデータを受け取り、**冪等キー `H`** を使ってデータベースに記録します。
    

システムにおける**単一の真実の源（Single Source of Truth, SSOT）は、DBノード群が分散保持するWitnessログ**です。各DBノードはオンメモリデータベース（SQLite）で高速処理を行いますが、これはあくまでWitnessログから復元可能な「マテリアライズドビュー（Materialized View）」として扱われます。これにより、特定のDBインスタンスに依存するSPOFを排除しています。

## 3. 中核技術要素

### 3.1. 完全固定長パケット (352バイト)

システム内の通信は、**352バイト (2,816ビット) の完全固定長パケット**に統一されています。

- **外装 (32バイト)**: 通信経路を暗号化するための **AES-256-GCM** ヘッダです。
    
- **本体 (320バイト)**: 取引ID、タイムスタンプ、送金元/先ID、金額、電子署名など、取引の全ての情報が固定長のバイナリ形式で格納されます。
    

この固定長設計により、パース処理が高速かつシンプルになり、ネットワーク効率が最大化されます。

### 3.2. 監査証跡 (Witnessログ - 128バイト)

最終的に永続化される監査証跡（Witnessログ）も、**128バイトの固定長レコード**です。極めて軽量なため、オンメモリでの高速な検索と、ストレージへの効率的な保存が可能です。

### 3.3. 冪等性の保証

通信障害などで同じリクエストが複数回送られても、データが二重に記録されることはありません。これは以下の式で算出される**冪等キー `H`** によって保証されます。

```
H = SHA3-256(TxID || Timestamp_ISE)
```

DB層は、この`H`を主キーとして`UNIQUE`制約を課しているため、重複したデータは自動的に無視されます。これにより、システムのデータ一貫性が担保されます。

### 3.4. 暗号技術

- **AES-256-GCM**: ノード間の通信を保護する標準的な暗号方式です。
    
- **Ed25519**: 取引の正当性を証明するための電子署名アルゴリズムです。
    
- **ISE (Indistinguishable Signed Encryption)**: THP-CLEAR独自の暗号概念です。万が一データが漏洩しても、正しい署名がなければ無数の「もっともらしい偽情報」と区別がつかず、真のデータを特定できないようにするセキュリティ機構です。
    

### 3.5. VoidCoin

価値がゼロの監査用トークンです。物資支援の追跡やシステムテストなど、金銭価値を伴わない取引の事実を記録するために使用されます。制度的に投機利用が不可能なように、以下の厳格なルールが課せられています。

- VoidCoin同士の交換は禁止。
    
- ステーブルコインとの交換は、認可された交換所ノードが介在する場合のみ許可。
    

## 4. 実装と運用

### 4.1. 技術スタックとハードウェア

- **言語**: Go
    
- **データベース**: SQLite (各ノードのローカル・オンメモリDBとして使用)
    
- **ハードウェア**: HP Elite Mini 800 G9相当の省電力ミニPC
    
- **デプロイ**: Docker / Docker Compose
    

### 4.2. ビルドと実行

`Makefile`が提供されており、標準的な開発タスクは簡略化されています。

```
# Dockerコンテナをビルドして、コンテナ内でCIスクリプトを実行
make all

# ローカル環境でCIスクリプトを実行
make local

# 単体テストを実行
make test

# 統合テスト（SQLiteを使用）を実行
make itest
```

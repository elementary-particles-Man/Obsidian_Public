# ISE-FS Specification

## Draft v0.1

---

## 1. 目的と設計原則

### 1.1 目的

ISE-FS（Indeterminate Signature Encryption File System）は、以下を唯一の目的とする。

- **重要データをロストしない**
    
- **外部からの論理的改竄・ランサムウェアを成立させない**
    
- **破損時に論理修復が可能である**
    
- **行儀の悪いソフトウェアの存在を前提に、安全性を担保する**
    

速度、POSIX完全互換性、既存FSとの性能比較は設計目標に含めない。

---

### 1.2 基本原則

- 最小管理単位は **4096バイト固定チャンク**
    
- **write は即時反映しない**（キューイング）
    
- 真実の確定は **Commit 操作のみ**
    
- **削除は論理と物理を分離**
    
- 安全性を実装・運用・権限モデルの三層で確保する
    

---

## 2. チャンク種別

ISE-FS は以下の4種類のチャンクのみを持つ。

### 2.1 Initial Chunk（初期チャンク）

- FS の存在と所有を定義する最上位チャンク
    
- サイズ：4096B
    
- **3N 強制配置**
    
- 常時 3N 完全一致を運用要件とする
    

#### 主な内容

- FS Owner 情報
    
    - 実名は持たない
        
    - 「外部プログラムに秘密値を入力した結果のシグネチャ」
        
- FS 作成時生成鍵（512bit）
    
- HW 構成情報
    
- 作成時刻／更新時刻
    
- サブチャンク参照（Int64 配列）
    
- フッタ（整合性検証用）
    

#### 運用規則

- 初期化は **3N 完全一致成立時のみ完了**
    
- アイドル時に 3N 比較
    
- 不一致時：
    
    - HW チェック
        
    - 異常なし → 多数決修復
        
    - 異常あり → アラート
        

---

### 2.2 Index Chunk（インデックスチャンク）

- **フォルダ単位で独立**
    
- ディレクトリ構造の真実を保持
    
- **2N 強制**
    

#### 内容

- フォルダメタ情報
    
- エントリ列挙：
    
    - データチャンクID
        
    - 子フォルダ（Index Chunk）ID
        
- フォルダポリシー
    
- 世代情報
    
- 整合性フッタ
    

#### 特徴

- フォルダ単位で破壊影響を局所化
    
- 修復・再構築を局所で完結可能
    
- Commit により世代昇格
    

---

### 2.3 Data Chunk（データチャンク）

- 実データ保持用
    
- フォルダポリシーにより冗長性が決定される
    

#### 内容

- ヘッダ：
    
    - ファイル属性（名前、サイズ、時刻、Owner ID 等）
        
    - 次データチャンクID（EOF=0）
        
- データ本体
    
- フッタ（整合性／改竄検知）
    

---

### 2.4 Temporary Chunk（0Nチャンク）

- **冗長性 0**
    
- **ISE 対象外**
    
- 一時データ・キャッシュ用途
    

#### 特徴

- 一般権限で削除可
    
- Commit 対象外
    
- **非 0N への昇格不可**
    
- Index Log の真実参照対象にならない
    

#### 運用原則

- ルート直下以外で作成可能
    
- 行儀の悪いソフトウェアによる
    
    - 勝手なテンポラリ
        
    - キャッシュ
        
    - 作業ファイル  
        を完全に許容する
        

#### 重要ルール

> **0N チャンクは永久に 0N のままである**  
> 保護したい場合は  
> **非 0N ポリシーフォルダへコピーする**

---

## 3. フォルダポリシー

各フォルダは以下のポリシーを持つ。

- `data_redundancy`：`0N | 1N | 2N | parity`
    
- `index_redundancy`：常に `2N`
    
- `commit_required`：true / false
    
- `ise_enabled`：true / false（0N フォルダのみ false）
    

### ポリシー適用規則

- 新規作成時にのみ適用
    
- 既存データの昇格・降格は存在しない
    

---

## 4. ISE 適用方針

### 4.1 ISE 対象

- Initial Chunk
    
- Index Chunk
    
- 非 0N Data Chunk
    
- KeyMap / KeyRef Chunk
    

### 4.2 ISE 非対象

- 0N Temporary Chunk
    

---

## 5. 鍵管理（KeyMap）

- フォルダ単位で ISE 鍵（KeyRef）を持つ
    
- FS 内には **実鍵を保持しない**
    
- KeyRef は SU 鍵で封緘された参照情報
    
- KeyMap チャンクは **3N**
    

### SU 鍵

- FS 外部に存在
    
- 通常運用時はメモリ常駐しない
    
- Commit / Cleanup / Key 操作時のみ使用
    

---

## 6. 書き込みモデル

### 6.1 Write

- 即時反映せず、write-queue に格納
    

### 6.2 Commit

- 唯一の「真実確定操作」
    
- Index 世代昇格
    
- 冗長領域への反映
    

### 6.3 Truncate

- 保留中 write-queue の破棄
    
- 既存真実は不変
    

---

## 7. Cleanup（SU 専用）

- 物理削除
    
- 旧世代回収
    
- 空き領域確保
    
- Scrub / Repair
    

一般権限からは実行不可。

---

## 8. ランサムウェア耐性

ISE-FS は以下によりランサムを成立させない。

- 書けても Commit できない
    
- 冗長領域は Commit ゲートの向こう
    
- Index は 2N
    
- KeyMap は SU 鍵無しでは解釈不能
    
- 0N は真実になれない
    

---

## 9. 設計上の非目標

- 高速性能
    
- POSIX 完全互換
    
- 既存 FS 置換
